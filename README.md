# 🛍️ ShopGuard Starter

ShopGuard Starter — це окремий інструмент для підготовки Shopify-проєктів. Він завантажує тему в окремий клієнтський GitHub-репозиторій, де у гілках `master` і `dev` лежать файли Shopify-теми, а не код стартера.

Усі файли CLI, тести й налаштування лежать у корені цього репозиторію. Окремої вкладеної папки `shopguard-cli` немає. npm-пакет позначений як приватний — **не публікуйте його**.

## Що потрібно

- Node.js 22 або новіший
- Git
- Shopify CLI 4 або новіший — для команд, що звертаються до Shopify
- Окремий GitHub-репозиторій для кожного проєкту магазину; для коду магазину рекомендуємо приватний репозиторій і HTTPS
- WebStorm — рекомендований редактор для роботи з проєктом

## 🚀 Створити робочий проєкт

Тут є **дві окремі папки й репозиторії**:

```text
shopguard-starter/   ← CLI, його source, тести та npm-залежності
store-theme/         ← лише Shopify-тема в корені; це репозиторій для Shopify GitHub integration
```

Не створюй клієнтський репозиторій через **Use this template**: тоді в нього скопіюються `src/`, тести та інші файли стартера. Shopify GitHub integration очікує структуру теми в корені під’єднаної гілки. ShopGuard залишається окремо.

### Якщо GitHub-репозиторій уже створений

На GitHub створи окремий порожній репозиторій теми **без README, License і `.gitignore`**. Візьми HTTPS-адресу. ShopGuard не створює репозиторії та не пушить у них автоматично.

### Клонування й запуск

Клонуй стартер, відкрий його в WebStorm і передай домен магазину та адресу порожнього клієнтського репо:

```bash
git clone https://github.com/mudmykola/shopguard-starter.git
cd shopguard-starter
npm start -- --store назва-магазину.myshopify.com --repo https://github.com/OWNER/STORE-THEME.git
```

Для приватного репо використовуй GitHub CLI або системний credential manager; **не додавай токен у URL**.

Команда встановить і перевірить ShopGuard у папці стартера, підключить `sgd`, клонуватиме клієнтське репо поряд зі стартером (папка матиме назву репозиторію), увійде в Shopify та завантажить обрану тему до клієнтського репо. Стартовий код і Git-історія не копіюються.

### Якщо GitHub-репо ще немає

Просто не вказуй `--repo`:

```bash
npm start -- --store назва-магазину.myshopify.com
```

ShopGuard створить окрему локальну папку `назва-магазину-theme`, завантажить туди тему й підготує локальні `master` і `dev`. Пізніше створи порожнє GitHub-репо без README, License і `.gitignore`, додай його як `origin` і відправ гілки:

```bash
cd ../назва-магазину-theme
git remote add origin https://github.com/OWNER/STORE-THEME.git
git remote -v
git push -u origin master
git push -u origin dev
```

Якщо папка з такою назвою вже існує, задай іншу через `--project-dir ../інша-назва`.

У цих гілках коренем будуть Shopify-файли (`assets/`, `config/`, `layout/`, `locales/`, `sections/`, `snippets/`, `templates/` тощо). ShopGuard тримає `.shopguard` у локальному Git exclude; файл конфігурації не потрапляє в репозиторій.

Далі під’єднай `dev` до неопублікованої теми, а `master` — до потрібної Live-теми через **Shopify Admin → Online Store → Themes → Add theme → Connect from GitHub**. Під’єднання й публікацію виконуй вручну в Shopify Admin.

У WebStorm працюй у папці `STORE-THEME`. `sgd` вже під’єднаний локально з папки стартера й діє на поточну папку. Підтвердження вибирай стрілками; скасування стоїть першим. Завантаження теми під час `init` лише читає Shopify та пише локально — воно не пушить Git і не змінює магазин.

### Якщо створюєте нову тему

Для нового магазину ShopGuard може завантажити початковий шаблон Shopify локально:

```bash
sgd configure --store назва-магазину.myshopify.com --mode new
sgd init
```

У цьому режимі `init` не звертається до магазину: він завантажує skeleton у тимчасову папку, показує список нових файлів і копіює їх після підтвердження.

### 🧭 Якщо магазин уже має тему

`sgd init` показує теми вибраного магазину. Обери тему, з якої хочеш почати: зазвичай це **Live**, тобто поточна версія магазину. ShopGuard спершу завантажує її файли в тимчасову локальну папку, показує план імпорту й просить окремо підтвердити копіювання у проєкт. Існуючі локальні файли не перезаписуються. Shopify при цьому не змінюється.

За замовчуванням `sgd init` дає вибрати тему в терміналі. Або передай ID явно. Для старту з поточного коду магазину обери Live; неопубліковану тему — лише якщо хочеш взяти саме її версію:

```bash
sgd init --source-theme 123456789
```

| Поняття | Що означає |
| --- | --- |
| **Тема-джерело** (`--source-theme`) | Звідки `sgd init` скопіює файли у твою локальну робочу копію. Вибір джерела сам по собі не дозволяє завантажувати в цю тему. |
| **Тема для ручного `sgd push`** (`themeId`, `themeRole`) | Окрема явно налаштована ціль. Ручне завантаження дозволене лише в перевірену неопубліковану тему без GitHub Integration. |
| **Тема GitHub Integration** | Shopify синхронізує її з під’єднаною гілкою. У нашому рекомендованому флоу `dev` веде на неопубліковану тему, а `master` — на Live. |

`sgd init` записує ID поточної Live-теми як захисний орієнтир `liveThemeId`. Вибране джерело окремою Shopify-ціллю не стає. Якщо джерелом була Live-тема, її файли опиняються локально, а майбутній шлях у магазин проходить через GitHub PR. У рекомендованому GitHub-флоу **не запускай `sgd push`**.

Початкове завантаження **не завантажує файли в Shopify і не надсилає їх у GitHub**.

## 🌿 Робочий процес: feature → dev → master → Live

Для теми, яку ведеш через GitHub integration Shopify, використовуй таку схему:

```text
feature/назва-зміни
        │ PR
        ▼
dev ──→ під’єднана неопублікована dev-тема
        │ PR після перевірки
        ▼
master ──→ під’єднана опублікована Live-тема
```

### Один раз: підготуй GitHub і теми Shopify

1. Після `sgd init` базова версія є у локальних гілках `master` і `dev`. Додай GitHub-репозиторій проєкту як `origin` (якщо його ще немає) та надішли гілки:

   ```bash
   git push -u origin master
   git push -u origin dev
   ```

2. У Shopify Admin: **Online Store → Themes → Add theme → Connect from GitHub**. Під’єднай `master` до теми, яку після перевірки зробиш основною. Після публікації цієї GitHub-керованої теми кожне злиття в `master` оновлюватиме Live.
3. Так само під’єднай `dev` до іншої теми й залиш її неопублікованою. Це preview для перевірки.
4. У GitHub захисти `master`: вимагай PR і успішні перевірки, заборони прямий push та force-push.

### Щодня: розробляй через PR

```bash
# почни з актуальної dev-гілки
git switch dev
git pull --ff-only origin dev

# створи окрему гілку для задачі
git switch -c feature/header-menu
```

Працюй локально, запускай `sgd check`, потім надішли гілку й відкрий PR у `dev`:

```bash
sgd check
git add .
git commit -m "feat(theme): update header menu"
git push -u origin feature/header-menu
```

Після перевірок злий PR у `dev` і переглянь Shopify preview неопублікованої dev-теми. Коли все готово до Live — відкрий PR `dev` → `master`, перевір зміни ще раз і злий його. Саме злиття в `master` запускає синхронізацію з під’єднаною Live-темою.

Не зливай `dev` у `master`, поки не перевірив dev-тему.

Shopify GitHub integration двосторонній: збереження змін у Shopify Theme Editor також може створити коміт у під’єднаній гілці. Щоб зміни коду проходили через PR, редагуй тему локально й у GitHub; узгоджуй роботу в Theme Editor, щоб не створювати неочікувані коміти та конфлікти. Документація: [під’єднання Shopify до GitHub](https://shopify.dev/docs/storefronts/themes/tools/github) та [стратегія гілок для тем](https://shopify.dev/docs/storefronts/themes/best-practices/version-control).

У цьому процесі не використовуй `sgd push`: команда призначена для окремої unpublished-теми без GitHub integration. `sgd sync` отримує зміни з GitHub, але не замінює `git push` і PR.

## 🧰 Налаштувати інструменти

```bash
sgd setup
```

Це необов’язкові налаштування редактора, форматування та Theme Check у клієнтському проєкті. Команда не копіює вихідний код чи тести стартера. Перевір створені файли перед комітом; гілки, під’єднані до Shopify, не повинні містити `src/` або `dist/`.

Команда додає відсутні конфіги якості коду, налаштування редактора VS Code і workflow GitHub Actions для Shopify Theme Check. У WebStorm відкрий клонований проєкт як звичайний проєкт Node.js; форматування та перевірки виконуй командами нижче. Існуючі файли не перезаписуються. Якщо бракує пакетів, ShopGuard покаже команду встановлення й попросить підтвердження. Він визначає менеджер пакетів за lock-файлом або полем `packageManager` у `package.json`; якщо вибір неоднозначний, спершу вкажіть менеджер явно.

Додаткові опції:

```bash
sgd setup --hooks             # встановити локальний pre-commit hook
sgd setup --uninstall-hooks   # видалити лише hook, створений ShopGuard
sgd setup --e2e               # додати залежності Playwright та axe
```

Hook запускає перевірку форматування staged-файлів і `sgd check`. Він не перезаписує наявний hook і відмовляється працювати з налаштованим `core.hooksPath`.

## 🔎 Щоденна робота

```bash
sgd status
sgd doctor
sgd check
sgd dev
sgd sync --check
sgd pull --preview
sgd preflight --fetch
```

| Команда | Що робить |
| --- | --- |
| `sgd status` | Показує магазин, налаштовану ціль, baseline, гілку Git, `origin`, локальні зміни та стан інструментів. Для проблем виводить наступну дію. |
| `sgd doctor` | Перевіряє конфігурацію, структуру теми, Git, Node.js, Shopify CLI та залежності. Дає підказки з виправлення. |
| `sgd doctor --verify-store` | Після окремого підтвердження надсилає до магазину лише запит списку тем. |
| `sgd setup` | Безпечно додає відсутні налаштування для розробки. |
| `sgd check` | Перевіряє структуру теми, конфігурацію та доступні лінтери; для теми також запускає Theme Check. |
| `sgd format` | Форматує змінені підтримувані файли теми. Захищені JSON-файли пропускаються. |
| `sgd format --check` | Перевіряє форматування, не змінюючи файли. |
| `sgd dev` | Після перевірки магазину й підтвердження запускає preview у dev-темі та лишається активним, щоб Shopify CLI міг оновлювати його під час роботи. Зупини через `Ctrl+C`. |
| `sgd sync --check` | Після підтвердження отримує Git refs і показує відставання/випередження гілок. |
| `sgd sync` | Працює лише з чистим робочим деревом; може виконати тільки безпечний fast-forward поточної гілки. При розходженні зупиняється. |
| `sgd pull --preview` | Завантажує вибрану Shopify-тему в `.shopguard/snapshots/` і показує, що можна імпортувати. |
| `sgd preflight --fetch` | Після підтвердження виконує Git fetch і перевіряє гілки та зміни в захищених JSON-файлах. Не зливає гілки й не розгортає тему. |

### Імпортувати вибрані файли

Після перегляду snapshot можна додати лише нові файли. Існуючі файли не перезаписуються:

```bash
sgd pull --theme THEME_ID --files sections/example.liquid,snippets/example.liquid
```

### Перевірити стиль коду

`sgd setup` створює EditorConfig із двома пробілами, UTF-8, LF і фінальним переносом рядка. Для змін у Shopify-темі дотримуйтеся простих правил:

- Рендерте основний вміст через Liquid і HTML; JavaScript додавайте для потрібної взаємодії.
- Тримайте код секції, налаштування й стилі поруч; повторно використовувані частини оформлюйте як snippets.
- Для зображень використовуйте `image_url` та `image_tag`; не відкладайте завантаження головного видимого зображення.
- Обмежуйте глобальні CSS-селектори й непотрібні сторонні скрипти.
- Використовуйте семантичні HTML-елементи, доступні підписи, видимий фокус клавіатури та змістовний alt-текст.
- Текст для покупців зберігайте в locale-файлах і виводьте через фільтр `t`.
- Не перезаписуйте навмання `config/settings_data.json`, JSON-шаблони й section-group JSON: це дані, якими може керувати власник магазину.

Офіційні довідники Shopify: [Theme Check](https://shopify.dev/docs/storefronts/themes/tools/theme-check), [продуктивність тем](https://shopify.dev/docs/storefronts/themes/best-practices/performance) та [доступність тем](https://shopify.dev/docs/storefronts/themes/best-practices/accessibility). Для пошуку повільних Liquid-ділянок використовуйте [Theme Inspector](https://shopify.dev/docs/storefronts/themes/tools/theme-inspector).

## 🧪 Перевірити тему в браузері

У репозиторії є Playwright-тести з axe. Вони перевіряють наявність основного вмісту, доступність клавіатури, горизонтальне переповнення на мобільній, планшетній і десктопній ширині, а також WCAG-порушення.

Спочатку відкрийте preview потрібної теми й передайте її URL. Браузерні тести нічого не надсилають у магазин і без URL пропускаються:

```bash
npx playwright install chromium
SHOPGUARD_PREVIEW_URL="https://preview-url" npm run test:e2e
```

За потреби задайте сторінки через змінну `SHOPGUARD_PREVIEW_PATHS` — список шляхів через кому, наприклад `/, /products/example, /cart`:

```bash
SHOPGUARD_PREVIEW_URL="https://preview-url" \
SHOPGUARD_PREVIEW_PATHS="/,/products/example,/cart" \
npm run test:e2e
```

ShopGuard не створює preview і не входить у Shopify за вас. Переконайтеся, що preview URL доступний у браузері, де запускаються тести.

## 📤 Перегляд і завантаження змін у Shopify

`sgd dev` запускає довготривалий локальний preview. Перед запуском CLI перевіряє список тем і показує магазин та команду. Після підтвердження лишай процес запущеним у терміналі: Shopify CLI відстежує локальні файли та оновлює preview. Натисни `Ctrl+C`, коли завершиш роботу. Shopify CLI завантажує файли у development theme, тому перевір домен магазину перед підтвердженням. [Деталі режиму `theme dev`](https://shopify.dev/docs/api/shopify-cli/theme/theme-dev).

### 🔒 Як захищено Live

- `sgd init` і `sgd pull` лише завантажують файли з Shopify; вибір Live як джерела не завантажує файли назад.
- `sgd dev` запускає Shopify CLI для development-теми й вимагає підтвердити магазин.
- `sgd push` перед завантаженням і повторно перед самим запитом перевіряє роль теми в Shopify. Він відмовляється працювати з Live, з ID записаної Live-теми, з GitHub-під’єднаною темою та із захищеними файлами.
- У твоєму GitHub workflow гілка `master` під’єднується до опублікованої теми. Тому **злиття або прямий push у `master` оновлює Live**. ShopGuard не може перехопити GitHub-синхронізацію. Увімкни захист `master`: тільки PR, обов’язкові перевірки й заборона прямого push/force-push.

Ручна команда `sgd push` доступна лише для явно налаштованої **unpublished-теми, не підключеної до GitHub**. Спочатку перевір ID і роль теми в Shopify Admin, потім задай їх у локальному `.shopguard/project.json`. Позначку `github.connected: false` встановлюй лише після власної перевірки: ShopGuard не може прочитати цей стан із Shopify Admin.

```bash
sgd push --baseline
sgd push --files assets/theme.css,snippets/example.liquid
```

Перед завантаженням ShopGuard повторно перевіряє магазин і роль теми, порівнює файли з baseline, зберігає recovery snapshot, запускає Theme Check і просить підтвердження. Завантажуються лише вибрані файли; Live-тема, GitHub-підключена тема, видалення та захищений JSON блокуються. Команда не публікує тему й не виконує автоматичний rollback.

Якщо тема керується через GitHub, використовуйте налаштований GitHub workflow для цієї теми; не запускайте `sgd push`.

## Приватність і безпечна робота

- Starter може бути публічним. Репозиторії з кодом магазинів клієнтів зберігайте приватними.
- Для роботи з GitHub використовуйте HTTPS. Keeper SSH Agent не потрібен.
- Не зберігайте токени чи паролі в репозиторії, `.shopguard/project.json`, Git remote або командному рядку.
- Не комітьте локальні налаштування магазину, авторизацію, snapshots і baseline.
- Перевіряйте ціль і список файлів перед кожною дією, що звертається до Shopify або GitHub.
- ShopGuard не створює GitHub-репозиторії, не надсилає коміти, не публікує npm-пакет і не публікує Shopify-теми.

## Перевірки репозиторію

```bash
npm run check
```

Це запускає TypeScript-перевірку, ESLint і офлайн-тести CLI; Playwright-тести пропускаються, якщо не задано `SHOPGUARD_PREVIEW_URL`. Ця команда перевіряє сам ShopGuard, а не тему клієнта. Для теми використовуйте `sgd check` або `npm run lint:theme`.
